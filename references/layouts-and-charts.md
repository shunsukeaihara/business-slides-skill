# 使える本文構成・グラフ・チャート

## 選び方

見せたい関係から選ぶ。ページを埋めるために構図を選ばない。ここにある図は配置領域を示しており、すべての枠線・塗りを描く指示ではない。

以下の具体座標は1040×720px・本文幅996pxの作図例。マスタを変更したら、本文領域の幅・開始点・下端をマスタから取得して再計算する。16:9は[比率別の再配置](aspect-ratios.md)に従う。パンチラインなしならY=100〜120、有ならY=145〜170から始める。同じ列構成を上下で維持し、列幅・行高・開始位置を揃える。長文は左・上揃え、短い見出しと数値は中央揃えを基本に、実画像で調整する。

## レイアウト例

図中のラベル・行列の観点は使用例であり、固定の入力項目ではない。名称・用途は配置と関係を示す。比較尺度や順序など構造上の意味を保ち、具体的な見出しは内容から決める。

### L1：2列比較

```
          比較対象A                    比較対象B
 ───────────────────       ───────────────────
 説明・根拠                        説明・根拠
 箇条書き                          箇条書き
```

- 使う場面：2つの選択肢、現状と目標、2事例の比較。同じ比較軸を使う。
- X=22/532、W=486、列間24。見出しH=42、線は見出し下+47、本文は線下24程度。
- 見出しは中央、本文は左。左右の本文領域は同じ高さ。
- 失敗しやすい点：比較対象ごとに項目順が違う、片側だけ別サイズ、短い一文を広い箱の左端へ放置する。

### L2：3列の並列テーマ

```
   アイコン             アイコン             アイコン
   テーマA              テーマB              テーマC
 ───────────         ───────────         ───────────
   説明                  説明                  説明
```

- 使う場面：同格の3つの要素、特徴、役割、選択軸。順番は示さない。
- X=22/362/702、W=316、列間24。52pxのアイコンは列の左端+132。
- 同格の見出し・アイコンは各列の中央。説明は同じ上端から始める。
- 失敗しやすい点：アイコンだけ左寄せ、全列を装飾カード化、文章を無意味な大空白で上下に分ける。

### L3：行見出し＋説明

```
 [区分A]    説明
 [区分B]    説明
 [区分C]    説明
```

- 使う場面：分類、定義、課題と内容、原則と理由。
- 見出しX=22/W=274、説明X=326/W=692。3行ならH=116前後、行間18〜24。
- 見出しは薄灰・中央。説明は透明。情報量が同程度なら全行を等高にする。
- 失敗しやすい点：説明を全部囲む、見出しの幅が行ごとに違う、最長行だけ小さい文字。

### L4：行軸×列軸の比較マトリクス

```
                 対象A           対象B           対象C
                ──────          ──────          ──────
 [比較軸1]        内容             内容             内容
 [比較軸2]        内容             内容             内容
```

- 使う場面：共通軸での比較、決定事項と判断基準、複数対象の機能・状態。
- 行見出しX=22/W=144、本文列X=190/472/754、W=264、列間18。
- 行見出しで分割の意味を明示。記号は意味をラベルで定義する。
- 2行ならH=154〜174程度が出発点。短文は縦中央、長文は上揃え。列内で揃え方を無秩序に変えない。
- 失敗しやすい点：空白だけの行区切り、○△だけで評価根拠がない、色だけで優劣を伝える。

### L5：横型ステップ＋対応行

```
          <工程1>    <工程2>    <工程3>    <工程4>    <工程5>
 [担当]     主体       主体       主体       主体       主体
 [作業]     ・行動     ・行動     ・行動     ・行動     ・行動
            ・行動     ・行動     ・行動     ・行動     ・行動
             ▾          ▾          ▾          ▾          ▾
 [成果物]   成果物     成果物     成果物     成果物     成果物
```

- 使う場面：順序を持つステップと、各ステップに対応する複数の情報。担当・作業・成果物は行観点の例。等幅は時間の比率を示さない。
- 行見出しX=22/W=98、5列ならX=142から178間隔、W=164。
- 矢羽はY=158/H=98、担当Y=285/H=66、作業Y=365/H=174、成果物Y=589/H=66の例。
- 本文20px、行見出し22px、工程見出し24px。番号・節目は矢羽内に置く。異なる文字サイズの重ね配置を許容。
- 作業は1要素内の箇条書き。成果物は短い名詞句で上下・左右中央。
- 作業→成果物は前後の余白を取り、底辺が長い小さな三角形を列中央へ置く。
- 失敗しやすい点：抽象的な「事前」「途中」だけの工程名、浮いた節目バッジ、内容のない矢羽、作業と成果物の重複。

### L6：タイムライン・複数期間の帯

```
                 期間1     期間2     期間3     期間4
 対象A            [────────────]
 対象B                       [────────────]
 対象C                       [──────────────────]
```

- 使う場面：対象ごとの実施期間、並行関係、節目。説明だけなら図を省略して既存ページに一文で統合できる。
- 行見出しX=22/W=198、軸X=246〜1018、4区分なら各193。行高74前後。
- 縦軸を「何の予定か」、横軸を時間として明確にする。工程別に見るのか対象別に見るのかを混同しない。
- 期間幅は時間に比例。非連続の期間は帯を分ける。説明用の値は明示する。
- 失敗しやすい点：時間軸が列ごとにずれる、期間と工数を混同する、確定していない日程を作る。

### L7：複数レーンのプロセス

```
              段階1          段階2          段階3
 レーンA       作業 ───────────→ 作業
 レーンB             作業 ──────────────→ 作業
 レーンC       作業 ───────→ 作業 ──────→ 作業
```

- 使う場面：複数主体や複数の取り組みの並行・受け渡し。
- 左のレーン名W=160〜200、右に共通の段階軸。各段階のXを全レーンで統一。
- 連携点だけ接続線とラベルを付ける。すべての箱を矢印でつながない。
- 失敗しやすい点：時間と責任の軸を混同する、交差線が多い、同じ段階の幅がレーンごとに異なる。

### L8：要素間の関係図

```
                 [全体を調整する主体]
                       関係ラベル
               ┌─────────┴─────────┐
           [主体A]               [主体B]
            対象範囲              対象範囲
```

- 使う場面：主体間の連携、管轄、支援、供給、協力などの関係。
- 箱は同じ階層で同サイズ。矢印・線には「何を渡す／担うか」を短く記載。
- 包含は囲み、方向のある受け渡しは矢印、因果は低い三角形。違う関係を同じ記号で表さない。
- 失敗しやすい点：特定の役職名をテンプレート化する、全箱を色分けする、実際にない指揮命令関係に見せる。

### L9：階層・分解ツリー

```
 [上位概念] ─┬─ [下位A] ── 説明
             ├─ [下位B] ── 説明
             └─ [下位C] ── 説明
```

- 使う場面：構成要素、分類、上位方針と具体項目、全体と部分。
- 階層ごとにXと幅を固定。接続線は黒を基本に補助線のみ薄灰とし、箱や文字へ食い込ませない。
- 上位の説明は上位に集約し、下位へ重複して書かない。
- 失敗しやすい点：階層と順序を混同する、下位項目の粒度が揃わない。

### L10：対象範囲・対応マップ

```
                   選択肢A    選択肢B    選択肢C
 領域1              対応       —          対応
 領域2              対応       対応       —
 領域3              —          対応       対応
```

- 使う場面：対象範囲、適用・非適用、対応能力、役割の分担。
- 列見出し・記号は中央。行の説明は左。必要な行見出しだけ薄灰。
- 記号の意味と未確認の状態を区別する。未確認を非対応と扱わない。
- 失敗しやすい点：チェックの量を価値の高さとして誤読させる、基準が列で異なる。

### L11：並列カラム＋共通項目

```
          [領域A]       [領域B]       [領域C]
           内容         内容         内容
         ───────────────────────────
                複数の領域に共通する内容
```

- 使う場面：個別の項目と、複数項目に適用される共通内容を整理する。
- 同格のカラムは等幅。共通領域は適用されるカラムの外端に揃える。
- 共通内容の種類は内容から決める。位置だけで支援・因果・前提の意味を付けない。
- 失敗しやすい点：下段を別の列数へ分ける、共通項目の重要性を面積だけで誇張する。

### L12：複数の入力→統合→結果

```
 [入力A]   [入力B]   [入力C]
       ＼     ｜     ／
         [判断・統合]
               ▾
             結果
```

- 使う場面：複数根拠からの結論、データと調査の統合、選定ロジック。
- 入力は同格なら同サイズ。統合部分に「どう判断したか」を記す。
- 失敗しやすい点：入力が並んでいるだけで結論の根拠が分からない、因果が証明されていないのに断定する。

### L13：共通構成の並列比較

```
           事例A                       事例B
 ─────────────────         ─────────────────
 状況・条件                       状況・条件
 取り組み                         取り組み
 結果・示唆                       結果・示唆
```

- 使う場面：複数事例、検証結果、施策の比較。
- 共通の観点を同じ順序で並べ、同じYに同じ情報役割を置く。条件・取り組み・結果は使用例。
- 画像が必要なら同じ寸法・トリミング基準。長文の資料画像だけで説明しない。
- 失敗しやすい点：片側は成果、片側は紹介文で比較不能。出典を文字サイズで隠す。

### L14：定性コメント・引用の比較

```
 [発言主体/属性]   コメントの要点
 [発言主体/属性]   コメントの要点
 [発言主体/属性]   コメントの要点
```

- 使う場面：インタビュー、観察、利用者の声、視点の違い。
- 主体の表記と本文を近接。長文は意味を保った要約とし、要約を逐語引用に見せない。
- 吹き出し・人物アイコンは必要な場合だけ。誇張した引用符で面積を使わない。
- 失敗しやすい点：一部の意見を全体傾向と扱う、発言主体・条件が不明。

### L15：画像・画面＋説明

```
          画像・画面（約60%）      見るべき箇所
                                   説明
                                   示唆
```

- 使う場面：外観、実物、画面、成果物の具体像。
- 6:4を出発点に内容で調整。画像の縦横比は保持。重要箇所は番号と近接説明で対応。
- 4点程度のギャラリーなら同じ寸法の小組を2×2にし、画像・ラベル・説明の高さを揃える。
- 失敗しやすい点：画面内の小さい文字に説明を任せる、画像だけで重要な主張を伝える。

### L17：図表＋説明

```
             図表（約2/3）           読み取り
                                      根拠
                                      判断への意味
```

- 使う場面：数値の傾向と意思決定上の意味を同じページで示す。
- 図表X=22/W≈640、説明X≈700/W≈318。図表領域に単位・ラベル・必要な注記を含める。
- 右側は図表の数値を全部読み上げず、差・変化・例外を説明する。
- 失敗しやすい点：図表より解説が長い、関連しない要点を右側へ詰め込む。

### L18：単一の図・主張、または上下の役割分担

```
                 主となる図・説明
```

または

```
          同じ軸で並べる確認事項・比較

          全幅の依頼・条件・結論
```

- 使う場面：単一の説明で完結、上段の根拠と下段の依頼を分ける。
- 単一なら箱や重複見出しを付けない。上下型でも列分割は上段の1組だけ。
- 短い依頼は中央、幅を使う長文は左。意味境界で改行してよい。
- 失敗しやすい点：情報が少ないだけのページを文字拡大で補う、必須でないまとめを下へ置く。

## 数量に応じたチャートの選択

以下は図の選択肢であり、すべてを使う指示ではない。原則として実データ・合意した仮定だけを図示する。単位・期間・母数・出典や条件を必要な位置へ記す。系列は黒・灰を基本とし、注目対象は独立したデータ系列色で強調する（color-system.md参照）。

| 使える構成 | 適した情報 | 配置・表現のルール | 避ける誤読 |
|---|---|---|---|
| 横棒・順位棒 | カテゴリ間の数量差、長い項目名 | 左に項目名、棒端に値。意味のある順序か値順 | 棒の原点省略、順序変更の理由が不明 |
| 集合棒 | 同じカテゴリの2〜3系列比較 | 同じ軸、系列順、棒幅を全カテゴリで統一 | 単位の異なる系列を同じ高さで比較 |
| 積み上げ棒 | 合計と内訳 | 共通の原点、合計を外側へ直接表示 | 中間区分の大小を正確に比較できると思わせる |
| 100%積み上げ棒 | 構成比の比較 | 0〜100%で統一、必要なら母数も併記 | 母数の異なる割合を件数と混同 |
| 折れ線 | 時系列の推移 | 等間隔の時間軸、系列を絞り終点へ直接ラベル | 非等間隔の時間を等間隔にする、欠損を連結 |
| スロープ | 2時点間の変化 | 左右の基準と単位を統一、両端に名称・値 | 2時点だけから経路・途中変動を推測 |
| ダンベル・ドット | 目標と実績、2群の差 | 同じカテゴリ行に2点と差を置く | 棒の面積が必要ない情報を大きな塗りで隠す |
| ウォーターフォール | 開始値から終了値への増減要因 | 浮動棒と合計棒を区別、計算が一致することを検証 | 因果根拠のない増減を原因として見せる |
| 散布図 | 2変数の関係、分布、外れ値 | 軸と単位、点の意味を明示。少数の重要点だけ注釈 | 相関を因果として断定する |
| バブル図 | 2変数＋量の3次元情報 | 面積を値へ比例、サイズ凡例、重なりを制御 | 半径を値へ比例して面積差を誇張 |
| ヒートマップ | 多数のカテゴリ×期間・評価 | 共通尺度と凡例。順序に意味を持たせる | 濃淡を主観評価の根拠にする |
| ヒストグラム | 連続値の分布 | 階級幅・境界・母数を明示 | カテゴリ棒と混同、都合のよい階級幅 |
| 箱ひげ・分布帯 | 群ごとのばらつき | 四分位・ひげ・外れ値の定義を示す | 平均だけの比較と混同、少標本を確かな差に見せる |
| 円・ドーナツ | 少数区分の全体構成 | 2〜5区分程度、合計・割合を直接表示 | 近い比率の厳密比較、3Dや多数の小片 |
| ファネル | 定義が揃う連続段階の残存量 | 段階定義と件数・率を併記。単純棒でもよい | 順序のないカテゴリを脱落過程に見せる |
| 小分割グラフ | 多数の系列を同じ条件で比較 | 同じ軸・サイズ・目盛、共通の並び | パネルごとの軸変更で差を誤認 |

## チャート主体の配置例

### C1：順位＋右の解釈

図表W=640、右説明W=318。棒は最大6〜8項目程度を目安に、項目名と数値を読める高さへ。長い項目名は左領域を広く取る。右には上位差・例外・意味を2〜3点だけ置く。

### C2：推移＋節目

図表を本文全幅へ。節目は該当する時点の近くへ小さな注記で置く。下部へ別の列構成を追加しない。全体の結論があればパンチラインに置く。

### C3：全体と内訳の比較

左に共通ラベル、中央に積み上げ棒、右に合計値を同じ行で並べる。内訳の直接ラベルが収まらなければ凡例を上へ1回だけ置く。各行は同じ高さ・軸範囲。

### C4：増減要因の橋渡し

開始値・寄与項目・終了値を左から右へ。合計と差分の形を分け、金額などの単位を軸付近へ表示。色は正負を説明する必要がある場合だけ増やす。差分の和を検算する。

### C5：散布図と象限

本文の2/3以上を散布図にし、閾値の根拠がある場合だけ象限線を引く。右側は注目点の解釈。位置を手で動かして重なりを解消しない。点の重なりは透明度・サイズ・ラベル位置で調整。

### C6：小分割の比較

2×2や2×3のパネル。各パネルは同じ軸・表示期間・凡例で比較可能にする。最大値が異なる場合でも、軸を変えるなら明示し比較目的と整合させる。

## 構成選択の最終確認

- 図形・矢印・色・幅・面積に、実際の情報と対応する意味があるか。
- 比較軸、時間尺度、単位、母数、条件が揃っているか。
- 原因と結果、前後関係、包含、分類、順位を混同していないか。
- 文章だけのほうが明快な内容に、図を強制していないか。
- 読者が判断するための情報があるか。装飾で密度を作っていないか。


全体→詳細、分解、絞り込み、評価、シナリオ、特殊チャートは[応用パターン](advanced-layouts.md)へ。

数値の強調は図表内の注目値や比較対象として行う。数字だけを並べるKPIグリッドは基本パターンに含めない。数値が主役でも定義・期間・母数・比較基準を保つ。
