# 複合分析のレイアウト

単独のグラフや箱を増やす前に、読者が対応づける必要のある情報を決める。ギャラリーG33〜G52は、二つ以上の情報の関係を一つの本文領域で説明する構成。会社マスタや特定の業務には依存しない。

## 対応関係の選び方

| 構成 | 使う場面 | 配置の要点・避ける誤読 |
|---|---|---|
| G33 列間対応マトリクス | 複数列の要素を同じ行で結び、対応やつながりを示す。 | 同じ行の要素を接続する。対応・順序・因果のどれを示すかは内容で定義し、単なる対応を因果と読ませない |
| G34 双方向関係図 | 要素間の双方向の関係を、向きとラベルで区別する。 | 要素を横に置き、往路と復路を離す。線の方向とラベルを対応させる |
| G35 マトリクス＋共通項目 | 行・列で項目を整理し、複数の項目に共通する内容を横断する領域にまとめる。 | 行・列の意味は内容から決める。共通領域は、その内容が適用される列の範囲をまたぐ |
| G36 段階別マトリクス | 段階を列、比較する観点を行に置き、各段階の内容や違いを整理する。 | 等幅の段階列に共通の行観点を置く。段階の順序を時間や量と混同しない。現在・目標の表示は必要な場合のみ |
| G37 ピラミッド＋詳細 | ピラミッドで階層構造を示し、各階層に対応する説明を並べる。 | 各階層と説明の高さを対応させる。階層名は内容から決め、面積を構成比と読ませない |
| G38 バブルチャート | 二つの数値変数を位置、第三の量を円の面積で示す。 | 円面積を第三の量に比例させる。座標・面積の尺度と単位を示す |
| G39 位置変化チャート | 二軸上の位置を結び、対象ごとの位置の違いや変化を示す。 | 両端が示す時点・条件と方向を定義する。実測の変化と想定する変化を区別する |
| G40 2軸配置＋詳細 | 二軸上の点や領域に対応する説明を、図の隣に示す。 | 点・領域の識別子を説明側でも使う。位置だけから優先順位や行動を自動的に導かない |
| G41 工程マトリクス | 順序を持つ段階を列、共通の観点を行に置き、各段階の内容を整理する。 | 全行で段階列を共有する。行には内容に必要な観点を置く |
| G42 全体・内訳チャート | 全体の一部を選び、その内訳を別の図で詳しく示す。 | 選択した部分だけを詳細に接続する。全体と詳細の分母を明示する |
| G43 スモールマルチプル | 共通の尺度と配置を持つ小さなチャートを並べ、複数対象を比較する。 | 比較する図で尺度・サイズ・系列順を揃え、行列の意味を途中で変えない |
| G44 条件×指標チャート | 条件を列、指標を行に置き、複数のチャートを共通グリッドで比較する。 | 同じ指標の行は尺度と単位を揃える。指標を成果・負担などに固定しない |
| G45 注釈付き折れ線グラフ | 折れ線上の注目点と、その説明を識別子で対応づける。 | 図上の注目点と説明の識別子を一致させる。グラフを多数の吹き出しで覆わない |
| G46 並列構成比チャート | 複数の構成比チャートを、共通の行・列の観点で並べて比較する。 | 行と列の観点を統一する。構成区分や母数が異なる場合は明示する |
| G47 構成比チャート＋コメント | 項目ごとの構成比と、それに対応する文章を同じ行に示す。 | 同じ項目の数値と文章を同じ行に置く。引用を使う場合は代表性を安易に主張しない |
| G48 横断プロファイル | 共通尺度の複数項目について、系列ごとの値を線で追って比較する。 | 項目間の尺度を揃える。項目を結ぶ線を時間変化と読ませない |
| G49 ペアドットチャート | 項目ごとに二つの値を点と接続線で示し、差を比較する。 | 同じ尺度で二点を結ぶ。差の単位を示し、割合とパーセントポイントを区別する |
| G50 属性比較マトリクス | 対象を列、属性を行に置き、共通の観点で特徴を比較する。 | 対象間で属性の順序を統一する。属性の種類は内容から決める |
| G51 項目別対応マトリクス | 一つの項目に関係する複数の情報を、同じ行の各列に対応させる。 | 同じ項目に属する内容を一行にまとめ、列の役割を明示する |
| G52 工程間依存フロー | 共通の段階軸に置いた要素間の依存関係を、接続線で示す。 | 共通の段階列を保つ。依存の向きと意味をラベル等で示し、線を箱間の余白へ通す |

## 複合構成の組み立て

- 左右に分ける場合は、例えば図60%・説明40%のように、情報の役割に合わせて比率を選ぶ。左右の高さと開始位置を揃える。下部に別の列構成を追加しない。
- 番号・対象名・同じ行位置を使って、どの説明がどの図に対応するか分かるようにする。色だけに対応関係を担わせない。
- 異なる種類の図を置くこと自体を目的にしない。互いに参照しない図なら、別ページに分けるか共通のグリッドを用いる。
- 多数の対象を見せる場合は、代表対象だけを恣意的に抜き出さず、対象の選び方とその他の扱いを説明する。
- 比較尺度・単位・母数・時点は図の近くへ。結論に不可欠な条件を小さい注記へ逃がさない。
- 本文領域の標準幅／ワイドを選び、領域全体は横中央。情報量が少ない図を最大幅へ引き伸ばさない。

## 実装

入力例は`assets/pattern-examples.json`、配置は`scripts/compound-patterns.mjs`。`build_html.mjs`からマスタの座標・色・文字サイズを受け取る。固定の会社ロゴや色を追加しない。見本を超える項目数・文章量では幅・高さ・ページ構成を再設計し、画像で確認する。
