# 複合分析のレイアウト

単独のグラフや箱を増やす前に、読者が対応づける必要のある情報を決める。ギャラリーG33〜G52は、二つ以上の情報の関係を一つの本文領域で説明する構成。会社マスタや特定の業務には依存しない。

## 対応関係の選び方

| 構成 | 使う場面 | 配置の要点・避ける誤読 |
|---|---|---|
| G33 環境→対応→成果 | 方針に至る理由を説明 | 同じ行で完結する3列。線は対応を示し、検証されていない成果を因果の事実にしない |
| G34 主体間の受け渡し | 提供物と対価・情報の往復 | 主体を横に置き、往路は上・復路は下。線の方向とラベルを必ず対応させる |
| G35 機能×責任＋横断基盤 | 全体の運営の仕組み | 列は機能、行は活動・責任・情報。共通基盤だけ全幅で下に置く |
| G36 成熟度と移行条件 | 現在から目標への段階 | 等幅の段階列に状態・移行条件・現在／目標を置く。成熟度を時間や量に見せない |
| G37 階層と具体化 | 上位の目的を下位が支える | 左の階層と右の説明を同じ高さで対応。ピラミッドの面積は構成比ではない |
| G38 規模を含むポートフォリオ | 二軸と規模を同時に比較 | 円の面積を量に比例させる。半径比例にしない。座標の定義と規模の単位を明示 |
| G39 位置の変化 | 現在と目標の違い | 現在点・目標点と接続を区別。計画上の移動を実績の推移と混同しない |
| G40 ポートフォリオ→対応 | 分類から行動を決める | 左の点・群の識別子を右の対応方針で繰り返す。位置だけで優先順位を決めない |
| G41 工程×対応範囲 | 工程全体の重点と欠落 | 上の矢羽は順序、行は機能や対象。未確認・対象外・未対応を区別 |
| G42 全体→部分の拡大 | 一部の内訳を説明 | 全体で選択した領域だけを詳細へつなぐ。詳細側の分母を明示 |
| G43 対象×指標の小グラフ | 同条件の複数比較 | 同じ列は同じ対象、同じ行は同じ指標・軸。縦横の意味を途中で変えない |
| G44 シナリオ×複数指標 | 成果と負担のトレードオフ | 列は同じ前提条件、行は別の指標。行ごとに尺度・単位を揃える |
| G45 注目点付き推移 | 変化と解釈を結ぶ | 図上の番号と右の説明を対応。小さい吹き出しをグラフ中に大量に置かない |
| G46 属性×複数質問 | 調査結果の共通傾向 | 同じ属性を行で揃える。質問・回答選択肢・母数が異なる場合は明示 |
| G47 数値×コメント | 定量と定性を併読 | 同じ項目の割合とコメントを同じ行に置く。引用の代表性を主張しない |
| G48 ベンチマーク・プロファイル | 項目ごとの強弱を比較 | 各行を共通尺度にし、同じ系列を線で追う。線の傾きを時間変化と読ませない |
| G49 二群の差 | 項目別の比較差を見せる | 2点を線で結び、差を近くに置く。割合とパーセントポイントを区別 |
| G50 セグメント別の対応 | 特徴に応じた施策 | 列は対象群、行は特徴・要求・障害・対応。ステレオタイプで内容を埋めない |
| G51 作業→検証→成果物 | 論点別の実行計画 | 1行1論点。単なる「検討」ではなく、何を見て判断するかを記載 |
| G52 並行作業と依存 | 取り組み間の受け渡し | 工程列を共通化し、接続は箱の間の余白を通す。受け渡す成果や条件を本文で明示 |

## 複合構成の組み立て

- 左右に分ける場合は、例えば図60%・説明40%のように、情報の役割に合わせて比率を選ぶ。左右の高さと開始位置を揃える。下部に別の列構成を追加しない。
- 番号・対象名・同じ行位置を使って、どの説明がどの図に対応するか分かるようにする。色だけに対応関係を担わせない。
- 異なる種類の図を置くこと自体を目的にしない。互いに参照しない図なら、別ページに分けるか共通のグリッドを用いる。
- 多数の対象を見せる場合は、代表対象だけを恣意的に抜き出さず、対象の選び方とその他の扱いを説明する。
- 比較尺度・単位・母数・時点は図の近くへ。結論に不可欠な条件を小さい注記へ逃がさない。
- 本文領域の標準幅／ワイドを選び、領域全体は横中央。情報量が少ない図を最大幅へ引き伸ばさない。

## 実装

入力例は`assets/pattern-examples.json`、配置は`scripts/compound-patterns.mjs`。`build_html.mjs`からマスタの座標・色・文字サイズを受け取る。固定の会社ロゴや色を追加しない。見本を超える項目数・文章量では幅・高さ・ページ構成を再設計し、画像で確認する。
