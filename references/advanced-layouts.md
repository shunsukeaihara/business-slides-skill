# 応用構成：対応・階層・数量

会社に依存しない構成カタログ。元資料の業界・社名・数値を条件にしない。本文領域をマスタから取得し、13:9／16:9で再計算する。L1〜L18と基本チャートは`layouts-and-charts.md`にある。

図中の文面は使用例。配置の関係は再利用し、見出し・観点・目的は資料の内容から決める。

## 選び方

| 読者が知りたいこと | 推奨 |
|---|---|
| 同じ項目に属する情報をどう対応させるか | L19 行対応マトリクス |
| 全体のどこを詳しく見ているか | L20 全体ナビ＋詳細 |
| どの要因が数値を決めるか | L21 演算付き分解 |
| 何を、どんな基準で残したか | L22 段階選別 |
| 条件が変わると何が変わるか | L23 シナリオ比較 |
| 判断の根拠が比較可能か | L24 評価表 |
| 各段階の内容や違いは何か | L25 段階別マトリクス |
| 何が何を強め、循環するか | L26 循環・フィードバック |
| 個別の内容と共通の内容をどうまとめるか | L27 マトリクス＋共通項目 |
| 要素間にどのような双方向の関係があるか | L28 双方向関係図 |
| 各項目に対応する複数の情報をどう読むか | L29 項目別対応マトリクス |
| 全体のどの部分の内訳か | L30 全体と部分の拡大 |

## L19：行対応マトリクス

```
              観察された事実       読み取り          判断・対応
 [論点A]          根拠               解釈              判断
 [論点B]          根拠               解釈              判断
 [論点C]          根拠               解釈              判断
```

- 列の情報役割を固定し、各行を1つの論点として完結させる。複数の事実から同じ判断なら行を集約。
- 行見出しは本文幅の12〜17%、残りを3列。事実が長ければ事実列を広く、根拠を短縮して意味を失わない。
- 事実と推測を表記で区別し、単なる同時発生を因果にしない。判断を繰り返す下部帯は不要。
- 4行以上の長文で窮屈なら論点を分ける。全セルを濃い箱で囲まない。

## L20：全体ナビゲーション＋詳細

```
 [全体の区分A]      選択した区分の名称
 [選択中の区分B]    ───────────────────
 [全体の区分C]      内容・根拠・図表
```

- 左を20〜25%、右を残りの幅。選択中だけ面または文字を強調し、枠線は黒・灰。選択と評価を混同させない。
- 本文は右側で完結。左右に対応線を入れるなら1本程度に留める。長い説明はナビへ置かない。
- 連続する詳細ページでナビ位置と順序を保つ。閲覧対象の切り替えがない単独ページではナビ不要。

## L21：演算付きドライバーツリー

```
                [要因A] ── 根拠・前提
 [指標] ＝      ×
                [要因B] ── 根拠・前提
```

- 分類ツリーと異なり、合計・積・差など演算を明示する。下位から上位を再計算できる構造。
- 左20%、中央30%、右45%程度。末端要因と根拠を同じ行に揃える。線を文字の下へ通さない。
- 単位と時点を合わせ、二重計上を検査。因果の強さや寄与率を矢印の太さで捏造しない。
- 多階層なら上位の分解と詳細を分ける。箱内に小グラフを入れる場合も軸と期間を統一。

## L22：段階選別と除外理由

```
 <候補抽出>          <条件で選別>          <詳細確認>
   対象数               残存数               残存数
   抽出条件             選別条件             確認条件
                        除外理由             除外理由
```

- 3〜5段階。工程名・対象数・条件を同じ列に置き、段階間で数が追えるようにする。
- 等幅の矢羽は手順を示す。幅で数量を表すなら共通尺度を使い、両者を混ぜない。
- 除外数・残存数の整合を取る。対象の重複・再追加がある場合は明示する。
- ダミーの候補粒子を大量に置かず、件数と代表条件を読みやすくする。

## L23：シナリオ×指標の共通グリッド

```
                  条件A              条件B              条件C
 [前提]           条件               条件               条件
 [指標1]          グラフ             グラフ             グラフ
 [指標2]          グラフ             グラフ             グラフ
```

- 前提条件と結果を対応させ、グラフは同じ指標の行で同じ軸・期間・系列順。
- 3列×2指標程度を出発点にする。凡例・単位は共通化。行・列見出しを省かない。
- 「予測」と「仮定による試算」を区別。幅や濃さで確率を示さない。値がなければ条件比較のみとする。
- 比率変更で増えた幅をグラフへ使う。条件文章を長くしてプロットを圧迫しない。

## L24：重視度＋達成度＋根拠の評価表

```
 評価軸           重視度       対象A       対象B       根拠
 比較項目1          高           3           2         説明
 比較項目2          中           1           3         説明
```

- 評価尺度の定義と未評価を明示。点数・達成度・重みは別物。記号だけで終わらせない。
- 評価セルは中央、根拠は左。注目列の枠線や薄い帯で視線を誘導し、全セルを色分けしない。
- 重みを使った総合値は算式を開示。等間隔でない順序尺度を安易に加算しない。
- Harvey ballを使うなら「0/4〜4/4」など同じ定義・数値ラベル。未確認は空円でなく「未確認」。

## L25：段階別マトリクス

```
               段階1          段階2          段階3          段階4
 状態          状態           状態           状態           状態
 移行条件      次へ進む条件   次へ進む条件   次へ進む条件   —
 現在位置                  現在／目標の表示
```

- 時間と成熟度を混同しない。階段の高さ・幅が定量値でない場合は順序モデルと明示。
- 各段階に共通の行観点を置く。現在・目標・移行条件は使用例であり必須ではない。活動・特徴・内容など必要な観点を選ぶ。
- 内容が長ければ等幅グリッド。階段・S字曲線は段階の関係を説明できる場合だけ使う。

## L26：循環とフィードバック

```
 [行動A] ──関係──→ [変化B]
    ↑                 ↓
 [行動D] ←─関係── [変化C]
```

- 3〜5要素。接続ラベルに「何がどう影響するか」を短く書く。循環が成立する前提も必要。
- 円形矢印で文章を曲げず、直立したテキスト箱と接続線で読む。箱は矩形を基本にする。
- 一方向の工程を循環に見せない。抑制・促進を示すときは＋／−の定義を置く。
- 定量モデルがない場合、線の太さや距離で効果量を表さない。

## L27：マトリクス＋共通項目

```
                 領域A           領域B           領域C
 階層1           対応            未確認          対象外
 階層2           一部対応        対応            対応
 共通項目                  複数列に適用する内容
```

- 既存のL10とL11を、階層と範囲の判断のために組み合わせる。列構成は上下で変えない。
- 共通領域はその内容が適用される列の範囲に合わせる。下段にあるだけで「支える基盤」という意味を持たせない。状態を表す場合は対象外・未対応・未確認を分ける。
- ロゴのタイルで埋めるより、対象名と意味のある状態を置く。対応の多さを優位性と断定しない。

## L28：双方向関係図

- 主体を左→右、必要なら提供者／仲介／利用者の共通レーンで配置。往路・復路をずらし、線の交差を減らす。
- 線に「提供物」「対価」「情報」等のラベル。接続線は黒・薄灰とし、方向と意味を文字で区別。
- 中央ハブを置くのは実際に集約機能がある場合のみ。単なる関係図を支配関係に見せない。
- 絵で具体像を示す場合も、詳細な説明は近くの本文へ。素材を増やすほどよいわけではない。

## L29：項目別対応マトリクス

- 一つの項目に関する情報を同じ行に並べ、列見出しで各情報の役割を示す。
- 行項目と列観点は内容から決める。見本の「論点・検証・証拠」は使用例であり、必須の列ではない。
- L19と同じ行対応の構成を応用できる。必要な列数・幅・結合範囲は情報量と関係で決める。
- 検証計画に使う場合は、予定と実施済みを区別し、何を確かめるかを具体化する。

## L30：全体の一部を拡大する

- 左の全体図で対象部分を中立色の枠線または面の強調で特定し、右の内訳図へ細い補助線でつなぐ。
- 詳細側に「何を分母とするか」を明示。全体の比率と部分内の比率を同じ値として並べない。
- 円の切片を無理に引き離すより、積み上げ棒の対象区分→詳細棒が読みやすい。
- 全体のその他要素は薄く残して文脈を保持する。左右を独立した関係のない図にしない。

## 高度なチャートの選択

以下の8種を基本16種に追加する。正確な比較なら単純な棒・点を先に検討する。

| 構成 | 向く情報 | 表現と注意 |
|---|---|---|
| 左右対向棒 | 共通項目に対する2群の量 | 中央ラベル、左右の原点と最大値を一致。左向き棒を負数と混同させない |
| 発散棒 | 正負の変化、基準からの差 | 0を共通中心にし、符号と単位を直接表示。否定回答の割合など非負量を負値へ見せる場合は意味を明記 |
| レンジ＋代表値 | 最小最大や区間、中央値 | 線で範囲、点で代表値。信頼区間と観測範囲を区別。点は必ず区間内 |
| マリメッコ | カテゴリ規模と内部構成 | 幅=カテゴリ全体量、高さ=内部比率、面積=部分量。棒幅の意味を明示。細かい区分なら棒へ戻す |
| パレート | 寄与の集中と累積割合 | 降順棒＋累積0〜100%。母数と累積値を検算。別単位の二軸で相関を作らない |
| シナリオ帯 | 時系列の複数の仮定範囲 | 実績と試算を線種・領域で分ける。帯を確率区間と呼ぶには根拠が必要 |
| 地域分布図 | 地理的位置や地域差 | 正確な地図と出典を用意。件数は比例記号、比率は面の濃淡を検討。面積の大きさを値と誤認させない |
| 指数化した推移 | 規模の違う系列の相対変化 | 基準時点=100等を明示。絶対量の大小は分からないことを保持。ゼロ・負値からの指数化は不適切 |

レーダー図は軸順で形・面積が変わるため、形状の概観に限る。厳密な比較は共通尺度のドット図へ。複合・二軸図は軸の単位を目立つ位置で示し、軸設定による見かけの一致を避ける。多数の円・ドーナツを並べるより、同じ原点の棒を優先する。

## 図の情報密度を上げる方法

1. 共通のラベル・単位・凡例を1回に集約する。
2. 比較軸の順序を揃え、対応を線ではなく位置で読めるようにする。
3. 特筆する箇所だけを中立色の枠・線や、文字・面のアクセントで示す。強調する理由を近接する文章に置く。
4. 実績・予測・仮定、確定・未確認を表記で区別する。
5. 余った領域に装飾を足す前に、根拠や条件が欠けていないか確認する。

複雑な形そのものを採用理由にしない。立体ピラミッド、歯車、天秤、ジグソー、太い回転矢印などは、矩形・線・表で同じ関係が読めるなら簡略化する。
