# 役割別カラースキーム

配色は会社別マスタの `colors` で定義する。レイアウト側には色コードを書かず、意味に対応するトークンを使う。ブランド色を変更しても構造線やデータ系列が連動して変わらない設計とする。

## 文字と面

| トークン | 標準値 | 用途 |
|---|---|---|
| `background` | #FFFFFF | スライド背景 |
| `text` / `coverText` | #111111 / #000000 | 通常の文字／表紙文字 |
| `muted` | #777777 | 注記・補助文字。主要な説明を薄くしない |
| `surface` | #F1F2F4 | 見出し・分類・包含を示す面 |
| `accent` | #294285 | 意味のあるテキストやボックスの塗りの強調 |
| `onAccent` | #FFFFFF | アクセント塗り上の文字 |
| `headerFill` / `onHeader` | #4B4B4B / #FFFFFF | 濃灰の帯見出しとその文字 |

アクセントは基本的にテキストかボックスの塗りに使う。全見出しを一律に着色しない。意味のない装飾線・枠・アイコンをブランド色にしない。囲みで強調する場合も枠線は中立色とし、必要なら箱の面や文字で強調する。文字と背景の組み合わせは読みやすさを画像で確認する。白文字は淡い面に置かない。

## 構造を示す線

| トークン | 標準値 | 用途 |
|---|---|---|
| `connector` | #000000 | ボックス間の接続、関係図、ツリー、ピラミッドの輪郭・区切り、工程線 |
| `connectorMuted` | #C5C8CC | 補助的な関係線。重要な関係は黒にする |
| `border` | #777777 | ボックス・包含範囲の枠 |
| `divider` | #777777 | 列・行見出しの区切り |
| `line` | #D3D6DC | 薄い罫線・グリッド |
| `rule` | #333333 | タイトル線、チャート軸などの主要な基準線 |
| `footerLine` | #CBD0D2 | フッター区切り |

関係線は黒を基本に、補助的なものだけ薄い灰色にする。色で関係の種類を増やさず、方向・実線／破線・ラベルで区別する。ピラミッドやハブ＆スポークの線にアクセントを使わない。線矢印の鏃は線と同色の塗りつぶし三角形とし、輪郭だけの鏃や文字記号で代用しない。箱間の因果を示す独立した三角形も塗りつぶし、底辺が長く高さが低い形とする。矢羽の箱は面の配色規則に従う。

## データを示す色

`series` はブランドの `accent` と独立したデータ系列用配列。標準は #294285、#7E8DAF、#BCC3CF、#E4E7ED。折れ線・棒・点・面など、データそのものにのみ使用する。折れ線が群青でも、周囲の軸・補助線・説明への接続は中立色とする。

- 同じ系列はページをまたいでも同じ色。順序・大小には明度の順序を持たせ、無関係なカテゴリに濃淡で順位を暗示しない。
- 比較が主目的なら黒・灰を基本に必要な系列だけ強調する。系列数を増やすためにアクセントを流用せず、マスタで区別できる系列色を定義する。
- 直接ラベル・凡例・線種も併用し、色だけで意味を伝えない。小さな薄色線は視認性を確認して濃くする。
- 赤・緑などの状態色は標準では持たない。意味が必要な案件に限り、マスタに意味と色を定義し、ラベルも付ける。

## 制作・検証

1. 色を置く前に役割（文字・面／構造／データ）を決める。
2. カスタムHTMLも同じトークンを使う。アクセントを構造線に転用しない。
3. 両比率の画像で、線の主従・文字のコントラスト・強調の量を確認する。
4. PowerPointでは塗りつぶした鏃を編集可能な図形で保持し、変換後にも確認する。

旧マスタに新しいキーがない場合、同梱生成補助は上記の中立色を補完する。新しいマスタには役割を明示して記載する。
