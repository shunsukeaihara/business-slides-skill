# 階層・判断・実行の構成

列を増やす前に、情報の階層と対応関係を決める。見出し・対象・根拠・判断の役割を区別し、複数行に共通する内容は必要に応じて一つの領域にまとめる。会社名・色・ロゴに依存しない。

## 選び方と配置

| 見本 | 使える構成 | 向いている内容 | 配置の要点 |
|---|---|---|---|
| G53 `grouped-rows` | 親子行と共通対応 | 複数の課題を束ねて施策に接続 | 親ラベルは対象行の高さを合計。共通対応も同じ行範囲に合わせる |
| G54 `nested-columns` | 二段の列見出し | 重要度と適合度など、異なる比較軸 | 親見出しは子列の幅と間隔の合計。子見出しの高さを統一 |
| G55 `vertical-process` | 縦工程＋詳細 | 工程ごとの作業と成果物 | 工程は短いラベル、作業は箇条書き、成果物は中央揃え |
| G56 `classification-actions` | 分類と対応方針 | 対象を段階的に分類して判断 | 親子の件数を整合。区分の面積を件数の大きさと誤認させない |
| G57 `numbered-narrative` | 番号付き方針と根拠 | 長めのエグゼクティブサマリー | 番号は細い列、文章は広く。見出しの下に根拠をまとめる |
| G58 `workpackage` | 作業・成果物・前提条件 | 検討計画や作業パッケージ | 作業欄を広く取り、成果物と条件は狭い同一列にまとめる |
| G59 `share-explanation` | 構成比の変化と理由 | 現状と目標、二時点の内訳比較 | 両棒の全高を一致。説明は積み上げと同じ順序にする |
| G60 `stage-gate` | 工程・成果物・移行条件 | 段階的な検証や展開 | 一つの時間軸を全行で共有。成果物と判断条件を混同しない |

## 結合と階層のルール

- 行をまたぐ箱は「同じ内容が適用される範囲」を表す。空白を埋めるための結合はしない。
- 親見出し・子見出し・詳細は別の情報階層。親見出しは短くし、長い説明を入れない。
- 親見出しの幅は子列の外端に揃え、別グループとの間は余白で切る。罫線を全面に連結しない。
- 一つの共通グリッド内で行や列を結合することは可能。上段と下段で無関係な列分割を作らない。
- 結合領域のテキストは、その箱の内部テキスト。箇条書きは一つの領域内の段落として保持する。
- 行の高さは内容量に合わせるが、同じ行内は揃える。短いラベル・成果物は上下中央、長文や箇条書きは上揃えを基本とする。
- 二段見出しや多列では本文サイズを密度用に統一し、セルごとに変えない。収まらなければ説明の整理、列幅の配分、ページ分割を先に検討する。

## チャートと説明の接続

構成比比較は各時点の合計を100%とする。境界を結ぶ線は同じ分類の境界に接続し、線が示すのは構成比の差であって実際の移動量ではない。分類数が多い場合は内訳をまとめるか別ページに分ける。積み上げ順・説明順・色の意味を一致させる。注記は必要なものだけ図の近くへ配置する。

## 入力と実装

全見本の入力は `assets/pattern-examples.json`、実装は `scripts/structured-patterns.mjs`。13:9と16:9は列幅を再計算する。`grouped-rows` の `start` は0始まり、`span` は対象行数。親グループと共通対応は、それぞれ行範囲を隙間・重複なく指定する。`nested-columns` の見本は2グループ×2列、`classification-actions` は3つの末端、`stage-gate` は4段階を想定する。それ以外の件数は配置処理を調整し、画像検証してから使う。

見本は語数と項目数を固定した万能テンプレートではない。両比率で本文の外端・中央配置・見出し・最終行・共通領域の意味を確認する。HTMLからのPowerPoint生成は `dom-to-pptx-skill` を使用し、生成後の画像も確認する。

## カラムの見出しと入れ子

| 見本 | 構成 | 選ぶ場面 |
|---|---|---|
| G61 `box-columns` | ボックス見出し＋共通の行観点 | 各案の狙い・論点を同じ位置で比較 |
| G62 `circle-columns` | 円見出し＋要点＋本文 | 同格の短い概念を並列に説明 |
| G63 `nested-box-columns` | 親ボックスカラム＋子項目 | 方針と個別施策の所属を示す |
| G64 `label-columns` | ラベルと本文を対応させるカラム | 対象・進め方・判断などを読み比べる |
| G65 `table-dark-head` | 濃灰地・白文字の列見出し | 詳細な比較表で見出しを明確に分離 |
| G66 `table-plain-head` | 背景なし・太字・左揃え・上下中央の見出し | 文章主体の表を自然な読み順で示す |

- 円は同格の概念ラベルに限定し、面積は数値を表さない。長文は円の中へ入れず本文へ置く。円も内部テキストを持つ単一図形として出力する。
- 入れ子は親→子の所属を表すために使う。枠の中にさらに枠を重ねること自体を目的にしない。見本では親を列見出し、子を下段の行見出しにして、二重の外枠を省く。
- 列見出しは一律中央揃えではない。短い同格のラベルは中央、文章を読む表の見出しは左揃え・上下中央を選べる。選んだ形式は同じ表の全列で揃える。
- 濃灰地の白文字は見出し帯に限る。本文の色を増やさない。見本はマスタの `rule` と `background` 色を使うため、差し替えマスタでもコントラストを検証する。
- マルチステップは横矢羽（G14/G60）と縦工程＋詳細（G55）を、工程数と説明量で選ぶ。工程・作業・成果物・判断条件を別の役割として整理する。

## 情報の関係から抽象化する

見本の業種・会社名・用語を置き換えるだけでは汎用化にならない。次の三点を先に定義する。

1. **要素の役割**：背景、観察事実、判断、施策、実行条件、成果など。
2. **要素間の関係**：因果、所属、分類、比較、時系列、共通適用など。
3. **読み終えた後の判断**：何を選ぶか、何を確認するか、どこに注力するか。

| 伝える関係 | 汎用的な構成 | 見本・展開方法 |
|---|---|---|
| 複数の背景から対応方針へ | 背景 → 影響 → 方針 | G33。行数が異なる場合はG53の共通領域を使い、同じ対応を繰り返さない |
| 対象を条件で分類して対応を分ける | 全体 → 分類 → 判定 → 対応 | G56。親子の対象範囲と件数を整合させる |
| 施策を成立させる条件を確認する | 施策群 → 実行条件 | G58の左右構成を用い、右側を組織・役割・仕組み・管理方法などの必要な観点に変更する |
| 複数の対象に共通する仕組みを示す | 個別事項＋共通機能 | G53。共通機能の箱は対象となる行範囲だけをまたぐ |
| 過去の変化から今後の対応を導く | 対象 → 変化 → 見通し → 根拠 | G54/G64の列構成。増減の矢印だけでなく評価基準と理由を添える |
| 共通の方向性の下で施策を整理する | 方針 → 子テーマ → 施策 | G63。親子の関係と並列の関係を混同しない |
|段階ごとに参加者や運営方法が変わる | 時間軸×構成要素 | G60。工程名を列見出し、参加者・提供価値・運営方法を行見出しにする |
| 一つの全体像から論点を掘り下げる | 全体像＋焦点の詳細 | G04/G58。選択した要素と詳細を同じ名称・番号で対応させる |
| 選択肢ごとの成功条件を比較する | 対象 → 成功条件 → 対応方法 | G65/G66。説明量に応じて列幅を不等配分する |

円やアイコンは情報の種類を識別するために使う。大きな円環・上昇矢印は成長や循環が本当に主題のときに限り、論点の列挙を無理に図形化しない。多対一の関係を一対一の矢印に変えて意味を歪めない。文字色は根拠なく強調に使わず、主張と裏付けは太字・段落・余白で区別する。

G67 `circle-row-columns` は、楕円の行ラベルと複数の比較列を組み合わせる円カラム。G62の横並び円見出しとは別構成。円・楕円の面積を値として扱わず、同格の対象を識別するために使う。

## 縦に進むステップの選択

- G55 `vertical-process`：工程・作業・成果物を共通列で対応させる。
- G70 `vertical-steps`：番号と縦の接続線を軸に、工程見出しと説明を並べる。枠を増やさず、検討の流れをすっきり読ませる。`steps`内の`label`と`tasks`を指定する。2〜4工程。
- G71–G74 `vertical-arrow-steps`：下向き矢羽を縦に並べ、各工程の説明を右に対応させる。2〜4工程に対応。
- `columnsMode: "three"`：矢羽内の短い文字（`short`）／独立した見出し（`label`）／本文（`tasks`）の3列。
- `columnsMode: "two"`：矢羽内の見出し（`label`）／本文（`tasks`）の2列。
- `arrowStyle: "pentagon"`：上辺は直線、下端が幅広の三角。`"chevron"`：上辺に三角の切り込みがある矢羽。途中で形状を混ぜない。
- 矢羽は同幅・同高・同じ間隔で置き、見出しは縦中央、箇条書き本文は上揃えにする。矢羽内文字は図形自身の内部テキストとし、PPTXでは編集可能なカスタム図形へ補正する。
- 短い工程名と少量の説明で時間軸を見せる場合は横型、長めの説明を対応させる場合は縦型を選ぶ。図全体の必要幅を決め、本文領域の中央へ配置する。
